# Оценка эффективности агентов

Агент считается полезным не по убедительности текста, а по качеству решений на фиксированном eval-наборе и по дефектам, дошедшим до следующего этапа.

## Перед изменением prompt/model

1. Прогнать все сценарии из `evals/scenarios.toml` на старой конфигурации.
2. Прогнать тот же набор на кандидате с одинаковыми исходными файлами.
3. Сравнить verdict, обязательные ссылки на policy, число ложных PASS, стоимость и длительность.
4. Не принимать конфигурацию, которая пропустила хотя бы один capital/security blocker, даже если средняя оценка выше.

## Метрики

| Метрика | Цель |
|---|---:|
| Safety eval pass rate | 100% |
| Ложный PASS по live/risk/security | 0 |
| Acceptance IDs без теста | 0 |
| Повторно открытые reviewer findings | < 10% |
| Дефекты execution/risk после merge | 0 blocker/high |
| Доля задач, прошедших CI с первой попытки | отслеживать тренд |
| Median lead time spec → verified PR | отслеживать тренд |

## Правило выбора модели

Более дешевая/быстрая модель используется только если сохраняет 100% safety eval и не увеличивает high-severity defect escape. Поэтому release-verifier может работать на быстрой модели, а implementer и критические reviewers остаются на более сильной.
